# 02. 시스템 아키텍처 — 단일 정본

> 이 문서는 qurator(HoneyFlow)의 **아키텍처 정본(canonical)** 이다.
> 5개 서브시스템 설계와 3종 검증(계정정지 레드팀 / 실사용성 / 기술 실현성)을 거쳐
> 발견된 모든 모순을 해소한 최종본이며, 구현은 이 문서와 [정책 시트](#13-정책-시트--모든-수치의-단일-정본)를 따른다.
> 계정 보호 규칙은 [03-account-safety.md](03-account-safety.md)가 별도 정본이다.

## 0. 설계를 지배하는 결정 5가지

1. **계정에 닿는 것은 공식 API 또는 현표의 손가락뿐이다.**
   자격증명(OAuth)이 연결되는 채널은 카카오(나에게 보내기)·Meta·유튜브·노션 4개뿐.
   무신사와 카톡 오픈채팅은 "자격증명 제로" 채널로 코드 레벨에서 분류한다.
2. **크롤러는 없어도 제품이 돌아가는 보조 엔진이다.**
   수동 입력(모바일 공유·URL 붙여넣기·크롬 확장)이 1급 시민. 크롤러가 0이어도 핵심 가치
   (재입력 4~5회 → 0회, 고지 자동화, 죽은 링크 관리)는 100% 동작한다.
3. **사실과 문체를 분리한다.** 가격·재고·쿠폰·링크·고지는 DB → 결정론적 렌더러의 영역.
   AI는 훅·코멘트 같은 "문장 필드"만 생성한다. AI 전면 장애 시에도 파이프라인은 수동 모드로 동작.
4. **모바일 퍼스트, 텔레그램 단일 콕핏.** 현표의 딜 발견은 무신사 모바일 앱에서 일어난다.
   일상 루프는 **텔레그램 + 카톡 2개 앱 안에서 완결**된다. PC 확장·웹 대시보드는 보조.
5. **승인 없이는 1바이트도 외부로 나가지 않는다 (approval-first).**
   "자동 발행 모드" 토글은 만들지 않는다.

## 2. 컴포넌트 소유권 매트릭스

검증 단계에서 "같은 컴포넌트가 문서 2~3곳에서 다른 스펙으로 정의"되는 문제가 발견됐다.
재발 방지를 위해 **컴포넌트마다 정본 섹션을 1곳으로 지정**한다. 다른 문서는 참조만 한다.

| 컴포넌트 | 정본 | 비고 |
|---|---|---|
| 데이터 스키마 (전 테이블, status enum) | 본 문서 §3 | 다른 곳의 스키마 서술은 무효 |
| 렌더러 (최종 텍스트 조립) | 본 문서 §4 | AI 레이어·어댑터는 조립하지 않음 |
| 채널별 렌더 스펙 (길이·버튼·분할·고지 위치) | 본 문서 §4.3 표 1장 | |
| 스코어러 | 본 문서 §8.3 (radar 소유) | AI 레이어는 경계딜 판정 함수 1개만 제공 |
| 승인 카드·알림 수치 | 본 문서 §6 | 다이제스트 3회/일, 즉시 푸시 조건 포함 |
| 숏링크 | 본 문서 §10.1 (딜×채널 코드 단일 방식) | `?c=` 채널 파라미터 방식 폐기 |
| 링크 헬스체커 | 본 문서 §10.3 (워커 1개, publish 레이어 소속) | **정규 상품 URL만 접근** |
| 수집 정책 수치 | §13 정책 시트 | safety/radar 문서 간 수치 충돌 해소본 |
| 계정 보호 불변식·Never List | [03-account-safety.md](03-account-safety.md) | |

## 3. 코어 도메인 모델 (스키마 정본)

### 3.1 관계 개요

```
Creator 1─N Product 1─N ProductVariant
Product 1─N Deal 1─N CuratorLink (variant별 0..1, 대표 링크가 기본)
Deal 1─N ContentCard (channel별 활성 1개, 불변+버전)
ContentCard 1─N Post
CuratorLink 1─N ShortLink (딜×채널당 1개) 1─N ClickEvent
Deal 1─N PerformanceSnapshot (일×소스 단위)
Creator 1─N ChannelTemplate / StyleCorpus / FitRecord
```

- **`creator_id`는 1주차부터 전 테이블 FK** — 현표 1인 → 4,400명 SaaS 전환 시 스키마 변경 0 (RLS 멀티테넌트).

### 3.2 핵심 테이블

**products** — 무신사 상품 정규화 스냅샷. `musinsa_goods_no` 자연키,
`canonical_url`(`www.musinsa.com/products/{no}`), 브랜드/상품명/품번(JSON-LD `mpn`)/카테고리/정가,
`main_image_url`(og:image — **재게시 금지**, 내부 확인용), `source`('share'|'extension'|'paste'|'radar').

**product_variants** — 색상×사이즈. `stock_state`('in_stock'|'low'|'soldout'|'unknown') —
'S부터 품절' 훅 재료. 색상 대표 행은 `size_name=null`.

**deals** — 큐레이션 단위(같은 상품도 쿠폰이 바뀌면 새 Deal).
`status: draft → ready → published → expired → archived` (**유일한 정본 enum**).
`sale_price / discount_rate / coupon_code / coupon_desc / coupon_expires_at / final_price / ends_at`,
`hook_line`(AI 초안 → 사람 수정본), `curator_note`(168/62 사이즈 코멘트), `score / priority`.

**curator_links** — 큐레이터센터에서 **사람이 수동 생성**한 링크 저장소 (API 생성 불가가 전제).
`raw_url`(원본, utm_term ULID 포함), `ulid`(정산 매칭 키), `variant_id`(null=**상품 대표 링크 — 기본값**),
`health`('ok'|'soldout'|'coupon_expired'|'dead'|'unchecked'), `health_checked_at`.
> **대표 링크 1개가 기본, 색상별 링크는 옵트인.** 색상별 N개 생성은 큐레이터센터 왕복을 N배로 만들어
> 하루 15~25분을 소모하는 최대 병목이었다(실사용성 검증 치명 이슈). 클릭 후 무신사 페이지에서
> 색상 선택이 가능하므로 UX 손실은 제한적이다.

**short_links** — `code`(base62 6자, 딜×채널당 1개 발급), `target_url`(큐레이터 링크 **원형 무변조**),
`state`('active'|'dead'), `channel`. 도메인은 **현표가 DNS를 완전 소유한 전용 도메인**(§10.1).

**content_cards** — 렌더 결과물. **불변 + 버전**(`UNIQUE(deal_id, channel, version)`).
`channel`('kakao_open'|'threads'|'instagram_comment'|'instagram_caption'|'notion'|'youtube_desc'|'link_hub'),
`template_id`(재현성), `body_text / body_blocks`, `char_count`, `disclosure_ok`(**false면 발행·복사 API가 422 거부**),
`ai_generated_fields`, `approved_at`. 발행 후 수정은 새 버전 강제 + 기발행 Post에 'stale' 배지.

**posts** — 발행 이력. `mode`('auto_api'|'semi_copied'|'semi_sent_to_me'),
`status: pending → sent → confirmed | failed`. 반자동 채널은 **복사 시점을 presumed_done으로 간주**하고
확인 탭은 옵트인(검증 반영: 하루 20회+ 확인 탭 강요 금지). 미전송 건은 **저녁 요약 1회**로만 리마인드.

**performance_snapshots** — `(deal_id, date, source)` 스냅샷.
source: 'self_redirect'(자동) | 'curator_center'(수동 CSV/스크린샷 파싱) | 'youtube' | 'instagram'(API).

**click_events** — (short_link_id, ts, referer, ua_class, country). **IP 미저장**(봇 판정 후 폐기), 30일 후 일 단위 롤업.

**보조 테이블**: `channel_budget`(행동 예산 카운터), `circuit_state`(채널 서킷), `audit_log`(append-only),
`style_corpus`, `fit_records`(착용감 DB), `sponsor_deals`(협찬 파이프라인), `feedback`(승인/스킵/수정 라벨),
`llm_calls`(비용 미터링), `policy`(§13 정책 시트의 DB 형태 — **수치 변경은 사람의 명시 결정으로만**).

## 4. 렌더링 파이프라인 (사실/문체 분리 — 정본)

검증에서 "렌더러가 3곳(core/ai/publish)에 서로 다르게 정의"된 문제를 다음으로 통일한다:

- **AI는 문장 필드만 생성**: `hook_line`, `curator_note`, 채널별 톤 변형 훅. 완성 초안 전문을 LLM이 생성하지 않는다.
- **결정론적 렌더러가 최종 조립**: 템플릿(DB의 jsonb DSL) + deal_facts → ContentCard.
  고지·링크·가격은 AI가 접근할 수 없는 **시스템 슬롯**.
- **채널 어댑터는 얇은 `serialize()`만**: ContentCard.body_blocks → 채널 API 페이로드 변환. 어댑터의 자체 render()는 없다.

### 4.1 렌더 절차

```
render(deal_id, channel):
 1. Deal + Product + Variants + Links(health=ok) + Template(active) 로드
 2. guard: 살아있는 링크 0개 → 'NO_LIVE_LINK' 실패 / ends_at 경과 → 'EXPIRED'
 3. 변수 바인딩 + 조건부 섹션(쿠폰 없음, 단색 상품 등)
 4. disclosure 주입 — 채널별 고정 상수, 첫 줄 강제 (03 문서 §10 문구 표)
 5. 채널 제약 검증(글자수·링크수) → 위반 시 자동 축약 → 재검증
 6. disclosure_ok 재검증 → ContentCard insert (version+1)
```

- AI 초안 실패(10s 타임아웃) → 빈 훅으로 카드 생성, `ai_generated_fields` 표시, 현표 직접 입력.
  **렌더는 AI에 의존하지 않는다.**
- 출력 역검증: 초안 속 숫자(원, %, 사이즈)·URL을 deal_facts와 정규식 대조. URL은 화이트리스트
  (생성된 큐레이터 링크 + 자체 허브)만 — 프롬프트 인젝션이 임의 링크를 심는 경로 차단.

### 4.2 템플릿 변수

`{hook}` `{brand}` `{name}` `{style_code}` `{list_price}` `{sale_price}` `{final_price}` `{discount_rate}`
`{coupon}`(없으면 블록 생략) `{ends}` `{links}`(health=ok만) `{size_note}` `{shop_link}` `{disclosure}`(렌더러 하드코딩).

### 4.3 채널별 렌더 스펙 (수치 정본 — 표 1장)

| 채널 | 형식 | 하드 제약 |
|---|---|---|
| kakao_open | **풀 버전 1건이 정본** (텔레그램 코드블록·복사 웹뷰용, 길이 자유) | memo API 경로만 요약 렌더(고지 포함 ≤200자, 본문 실질 ~170자) + '전체 복사' 버튼 1개. **2분할은 최후 폴백** — 검증 반영: 200자는 memo API 제약이지 카톡 채널 제약이 아니다 |
| threads | 고지 첫 줄 + 본문 | ≤480자(500 한도 마진). **링크는 링크허브 1개로 접기가 기본값**(색상별 나열 금지 — 스팸 신호 완화). link_attachment 1개 |
| instagram_caption | 고지 첫 줄 + 캡션 | 300~600자, 릴스 자막 훅(≤15자) 별도 필드 |
| instagram_comment | 고정댓글: 고지 + 링크 목록 | 해시태그 금지 |
| notion | 최상단 고지 콜아웃 + 갤러리 + 링크 표 | 요청당 ≤1,000블록 (실제 ~30) |
| youtube_desc | **설명란 전체의 첫 줄(접힘 전 노출 영역)에 고지** + 관리 마커 구간 링크 | 레드팀 반영: 마커 구간이 하단이어도 고지는 항상 최상단 |
| link_hub | 상시 고지 배너 + 활성 딜 목록 | oos 자동 제외 |

## 5. 입력 레이어 — 모바일 퍼스트 캡처

실사용성 검증의 치명 이슈("현표의 딜 발견은 무신사 모바일 앱에서 일어나는데 설계가 PC 확장 중심")를 반영해
**4개 입력 경로를 등급 없이 동급**으로 설계한다.

| 경로 | 흐름 | 상태 |
|---|---|---|
| **모바일 공유시트 (1급)** | 무신사 앱 → 공유 → 텔레그램 봇 (URL 자동 파싱) | Phase 1 |
| 텔레그램 URL 던지기 | 봇 대화에 URL 붙여넣기 → 서버 단발 fetch(전역 레이트리밋 공유) | Phase 1 |
| 크롬 확장 (PC) | 상품 페이지 버튼 1클릭 → DOM/JSON-LD 추출 (§5.1) | Phase 2 |
| 웹 폼 | URL + 가격 수동 입력 (최후 폴백, **Phase 0의 유일 경로**) | Phase 0 |

- 크롤러 BLOCKED 시 모바일 폴백: 봇이 "상품 스크린샷을 보내달라" → Vision 파싱 → 확인 후 저장.
  **폴백이 "PC 앞으로 가라"가 되면 안 된다.**

### 5.1 크롬 확장 (MV3) — 경계

- content script: `www.musinsa.com/products/*` 만 host_permissions. **사용자 클릭 시에만 동작.**
- 추출 순서: JSON-LD → `__NEXT_DATA__` → DOM 셀렉터 폴백 → 수동 입력 폼. 원격 코드 금지(MV3).
- **금지 목록**: 백그라운드 fetch·주기 폴링 일절 금지 / 큐레이터센터 DOM 자동 조작(링크 자동 생성 매크로) 금지 /
  `cookies` 권한 미선언 / 이미지 다운로드·재업로드 금지 / 확장→SNS 자동 게시 금지(복사까지만).
- 배포: Chrome 웹스토어 Unlisted($5 1회). **스켈레톤을 1주차에 선제출**(심사 리드타임 수일~수주).

### 5.2 큐레이터 링크 입력 — 병목 해소 설계

무신사에 링크 생성 API가 없으므로 링크 생성 자체는 사람이 한다. 누적 시간을 최소화하는 3장치:

1. **대표 링크 1개 기본값** (색상별은 옵트인) — 센터 왕복을 딜당 1회로.
2. **텔레그램 봇 안에서 완결**: 승인 카드의 [센터 열기] 버튼(모바일 웹 딥링크) → 링크 복사 →
   **봇 대화에 그냥 붙여넣기** → 봇이 ULID 파싱·variant 매칭·카드 재렌더까지 처리. 앱 전환 최소화.
3. **배치 링크 세션** (아침 다이제스트용): 승인된 딜들의 상품번호를 순차 클립보드 큐로 제공,
   붙여넣기 필드도 순차 매칭 대기.
- '링크 생성 분/딜'을 주간 지표로 추적한다 — 시간 목표 달성의 최대 변수.

## 6. 승인 UX — 텔레그램 단일 콕핏

검증에서 "승인 카드 2벌(후보 승인 + 발행 승인) × 3앱 분산"이 지적됐다. **카드 1장의 상태 전이**로 통일:

```
[후보 카드] ─(관심 탭)→ [링크 대기 카드: 센터 딥링크 + 붙여넣기 안내]
           ─(링크 입력)→ [발행 승인 카드: 카피 미리보기 + 전체승인/채널별/훅교체/스킵]
           ─(전체 승인)→ 카드가 "발행 중 → 채널별 결과"로 실시간 갱신 + 카톡 코드블록 후속 도착
```

- **미리보기 원칙 (safety '본 것=나가는 것'과의 절충 확정)**: 카드에는 **채널 간 공통 가변부
  (훅+가격+쿠폰+링크)를 전문 표시**하고, 채널별 차이는 이미 검증된 고정 템플릿임을 시스템이 보증
  → "가변부 승인 = 전 채널 승인"으로 원칙을 재정의. **템플릿 버전이 바뀐 첫 발행만** 전 채널 전문 확인 강제.
  카톡·고정댓글 등 사람이 직접 붙여넣는 채널은 전송 직전 눈으로 보므로 이중 확인 성립.
- **수정 UX**: [훅만 교체] 버튼이 1급 — 답장으로 훅 한 줄 보내면 전 채널 카드 재렌더
  (사실/문체 분리 덕에 대부분의 수정이 훅 교체로 해결). 초안은 2안 제시 + 택1. 정밀 수정만 웹 이탈.
- **알림 수치 (정본)**: 다이제스트 **1일 3회 (09:30 / 14:30 / 20:30, 일별 ±30분 지터)**.
  즉시 푸시는 **Urgency ≥ 85, 1일 최대 5건**. 일일 후보 10~15건(콜드스타트기 20~30건).
- **방해금지 모드**: 촬영 시간대 설정 — 해당 시간의 긴급 딜은 '놓친 딜' 목록에만 적재하고
  **푸시·학습 라벨 양쪽에서 제외**. `expired`/auto-skip은 네거티브 라벨과 승인률 분모에서 제외(라벨 오염 방지).
- **승인 유효성**: 30분 타이머 재확인(알림 폭탄 원인)을 폐기하고 **상태 변화 기반**으로 —
  발행 직전 헬스 재확인이 통과하면 시간 경과와 무관하게 발행, 재고·쿠폰 상태가 변했을 때만 재확인 카드.
  배치 승인은 배치 단위 유효시간 2시간.
- **보안**: chat_id 화이트리스트. `/killall` `/resume` 등 파괴적 명령은 **인라인 재확인 + 4자리 코드 입력**,
  대시보드 웹에 동일 토글(텔레그램 탈취·장애 시 대체 경로). 봇 토큰도 Vault 관리 + 회전 정책.

## 7. 발행 레이어

### 7.1 어댑터 계약

입력은 항상 **ContentCard**. 메서드는 `serialize(card) → payload`, `validate(payload)`(고지·글자수 — 실패 시 발행 차단),
`publish(payload) → external_id`, `healthMeta(post)` 4개.
재시도: 지수 백오프 30s→2m→10m 최대 3회. 401/403은 재시도 금지 + 즉시 알림. 429는 Retry-After 준수.
3회 실패 → 해당 채널만 반자동 폴백(완성 텍스트를 텔레그램 전달) — **부분 실패가 전체를 막지 않는다.**

### 7.2 채널별 요약

| 채널 | 모드 | 핵심 |
|---|---|---|
| Threads | 자동 | 2단계 발행(컨테이너→publish), 멱등 체크(external_id). 링크는 허브 1개 접기 기본 |
| Instagram 피드/캐러셀 | 자동 | 발행 전 `content_publishing_limit` 실측 교차 확인. 릴스는 MVP 반자동(캡션+커버 전달) |
| IG '링크' 댓글 응대 | **자동 (링크 카드만)** | §7.4 — 정책 통일 확정 |
| 노션 | 자동 | 착장 DB + 페이지. 품절 시 취소선 패치(삭제 안 함) |
| 카카오 오픈채팅 | **반자동** | 주 경로: 텔레그램 코드블록(탭 복사) → 카톡 붙여넣기. 보조: 나에게 보내기(§7.5) |
| 유튜브 설명란 | 자동 | snippet 전체 선조회 후 병합(필드 소실 방지), update 전 스냅샷 저장(롤백). 고지 최상단 |
| 유튜브 고정댓글 | 반자동 | API에 pin 없음 — 완성 텍스트 전달, 사람이 붙여넣고 고정 |

### 7.3 발행 페이싱 (레드팀 반영)

- 채널당 최소 90초 + 지터 U(0,180s), 10분 창 최대 2건, 08:00~23:00 KST.
- **승인·발행 시간 분리**: 승인 건은 즉시 발행하지 않고 **다음 1~3시간 창의 랜덤 슬롯에 분산**
  (긴급 딜만 즉시 옵션) — "매일 09:35~09:50 발행 버스트"라는 스케줄러 지문 제거.
- Meta dev mode 기간: 발행량 추가 제한(일 5건 이하) + **App Review 통과를 출시 4주 내 마일스톤으로**.
- 신생 숏링크 도메인 웜업: 첫 2주 일 2~3건 램프업. 링크 없는 오가닉 포스트 30% 이상 혼합 권장
  (발행 큐에 '링크 무포함 콘텐츠' 슬롯).
- 재발행(재입고·마감임박)은 원발행과 텍스트 유사도 70% 초과 시 훅·구성 강제 변형, 딜당 채널당 최대 1회.

### 7.4 IG '링크' 댓글 → DM (정책 확정)

서브시스템 간 모순(자동 vs 초안만)을 다음으로 통일한다:

- **키워드('링크','크링') → 링크 카드 자동 발송 허용**: 사실만(상품명·색상·링크·고지), 문장 생성 없음.
  Private Reply(댓글당 1회, 7일 내) 공식 메커니즘. 상품명·색상으로 가변 렌더링(동일 문자열 반복 회피).
  일일 총량 캡 + 킬스위치 편입 + **도입 첫 2주는 일 30건 램프업**. 부정 신호(차단 등) 웹훅을 SignalCollector에 등록.
- **문장형 CS는 항상 초안 + 사람 수동** — 예외 없음.
- 단, 이 기능은 `instagram_business_manage_messages` 계열 고급 권한·비즈니스 계정 요건이 있으므로
  **구현 전 Meta 권한 매트릭스 실측**(dev 모드에서 웹훅+Private Reply 실동작 여부)이 선행 조건.
  실측 전까지는 반자동(텔레그램 알림 → 사람이 답글).

### 7.5 카카오 경로 (정본)

- **주 경로: 텔레그램 코드블록** — 길이 무제한, 탭 1회 복사, 카카오 계정에 자격증명 0개.
- **보조 경로: 나에게 보내기 memo API** — 카톡 안에서 완결되는 장점. 단 talk_message 스코프의
  앱 검수에서 "어필리에이트 메시지 중계" 사용 사례 판정이 미검증(레드팀 중간 이슈)이므로,
  **1주차 실측(검수 요건·쿼터) 후 도입 여부를 명시적으로 결정**한다. 검수 리스크가 있으면 텔레그램 단일 경로로
  시작(카카오 계정에 붙는 자격증명 0개가 원칙 1에 더 부합).
- **오픈채팅 게시 빈도 가드**: 일 3~5회 권고 상한을 대시보드 카운터로 표시(전송은 사람, 페이스는 도구가 관리).
  숏링크 도메인의 카톡 인앱 클릭 가능 여부를 주기 점검하는 카나리아 추가(도메인 스팸 등재 조기 감지).
  방 공지에 광고성 방임을 명시(오픈채팅 운영정책상 영리 목적 고지).

## 8. 딜 레이더 (Phase 3 — 크롤러는 보조 엔진)

### 8.1 수집 아키텍처

```
[Discovery/Tracker/HealthCheck 워커] → [Fetch Gateway (단일 진입점)] → [Raw Cache] → [Parser]
                                            │                                → [Product/Snapshot DB]
                                            └ 전역 토큰버킷·robots.txt·차단감지·킬스위치      → [Event Detector] → [Scorer] → 후보 큐
```

- **Fetch Gateway**: 모든 아웃바운드 HTTP의 단일 진입점. 전역 레이트리밋·백오프·킬스위치가 한 곳에서 강제.
  **쿠키 저장소 자체가 없고**, Cookie/Authorization 헤더 또는 **ULID/utm 파라미터 포함 URL은 하드 abort**
  (자기 클릭이 어뷰징 실적으로 잡히는 사고 원천 차단 — 헬스체커 포함 전 워커 공통).
- 인프라: MVP에서는 **크롤러 자체를 배제**(수동 입력+확장만). Phase 3 도입 시 1일차에
  Supabase/서버리스 IP로 접근 가능 여부 실측 → 막히면 **뚫지 않고 크롤리스 모드**로 확정하고 제휴 트랙 직행.
- 수치는 전부 [§13 정책 시트](#13-정책-시트--모든-수치의-단일-정본) — DB 설정 + 하드캡 이중화.

### 8.2 이벤트 감지

`PRICE_DROP`(직전가 ≥7% 하락 또는 30일 최저가 경신 — 30일 중앙값 대비 실인하율로 위장 인상 필터),
`COUPON_NEW` / `COUPON_EXPIRING`(≤24h, ≤6h 각 1회), `SIZE_SELLOUT`(S/M 품절 전환 + fast_sellout),
`SELLOUT_RISK`(≥40% 품절), `RANK_SURGE`(20계단↑ 또는 Top30 진입), `RESTOCK`, `DEAD_LINK`.
디바운스: 동일 상품·타입 12시간 1회. 재고 플래핑 3회/24h 초과 시 24h 뮤트.

### 8.3 스코어링 (정본 — 오너: 딜 레이더)

```
score = 0.40 × TasteScore + 0.35 × DealStrength + 0.25 × Urgency   (각 0~100)
```

- TasteScore: 브랜드·카테고리·가격대 발행 빈도 가중치(노션 40+ 페이지 임포트로 시딩) →
  성과 데이터 축적 시 성과 가중 평균(반감기 30일). 명시 신호 최우선(거부 1회 = 스킵 5회).
- **AI 레이어의 역할은 경계딜(40~75점) LLM 판정 함수 1개** — `{score_adj: ±15, reason}`. 그 외 점수식·정책은 여기가 정본.
- 콜드스타트: 온보딩 명시 입력(단, **Day 0이 아니라 사용 3~4일 후 분할 요청** — 검증 반영) + 2주간
  TasteScore 비중 0.40→0.25로 낮춰 광폭 추천, 라벨 100건 후 정상 복귀.
- 컷: score ≥ 60 큐 진입, 큐 상한 30, 동일 브랜드 최대 3건, 재발행은 별도 레인.
- 피드백 수신처는 **TasteScore 가중치 테이블 하나** (대시보드의 주간 EMA 배치가 여기에 쓴다).

## 10. 링크 시스템

### 10.1 숏링크 (단일 방식 확정)

- `{전용도메인}/{code}` — base62 6자, **딜×채널당 1개 발급** (채널 파라미터 방식 폐기 — 계측 확실성).
- 도메인: **현표가 DNS를 완전 소유한 신규 도메인 1개 확정**(예: `jenflox.link`) — jenflox.com은 온더룩
  호스팅 도메인이라 서브도메인 부착 가능 여부 자체가 미확인(실현성 검증 반영). 숏링크·복사 웹뷰·링크허브를
  이 도메인 아래로 통합. **1주차 구매**.
- 리다이렉트: 302 → 큐레이터 링크 **원형 무변조** (utm_source·utm_term 파라미터 보존 — 링크 변조 금지 조항 준수).
- **불변식 (레드팀 치명 이슈 반영): 자동 302의 최종 목적지는 절대 '다른 상품의 큐레이터 링크'가 될 수 없다.**
  죽은 링크는 반드시 **비커미션 안내 페이지**(자체 도메인)에 착지시키고, 대안 딜은 사용자가 페이지에서
  명시적으로 클릭해야만 커미션 링크로 이동(클릭 의도의 단절점). 이 불변식은 게이트웨이 코드 레벨로 강제.

### 10.2 안전 모드 (shortlink_mode 플래그)

- `policy.shortlink_mode: 'safe' | 'full'` — **기본값 safe**.
- **safe**: 자기 소유 지면(노션·링크허브)만 숏링크. 카톡·스레드·IG·유튜브는 **raw 큐레이터 링크 직노출**.
- **full**: 전 채널 숏링크. **무신사의 서면/공식 확인을 받은 뒤 사람이 전환** — 전환 이벤트는 audit_log 기록.
- 무신사 담당자 확인 요청은 "오픈 이슈"가 아니라 **1~2주차 액션 아이템(기한 명시)** 이다.
- safe 모드의 죽은 링크 대응: 카톡·스레드는 정정 메시지 재발송 플로우(정정문 원탭 생성)로 커버.

### 10.3 링크 헬스체커 (워커 1개 — 정본)

- **접근 대상은 커미션 파라미터 없는 정규 상품 URL(`musinsa.com/products/{no}`)만.**
  큐레이터 링크(ULID 포함)는 절대 방문하지 않는다 — Fetch Gateway가 하드 abort.
  (실현성 검증 치명 이슈: 이전 core 문서의 "큐레이터 링크 헬스체크" 문구는 **오류이며 폐기**.)
- 대상 축소(레드팀 반영): '발행 상품 전체'가 아니라 **최근 24h 클릭이 실제 발생한 링크의 상품** 중심
  (+ 발행 72h 이내는 무조건) — 조회 집합이 큐레이터 링크 목록과 1:1로 일치하는 지문 희석.
- 발행 시각과 첫 체크 사이 **랜덤 오프셋 1~6h** (동기화 신호 제거).
- 주기 티어: 발행 후 72h 이내 6시간 / 3~14일 12시간 / 14일+ 1일 1회 / 30일 후 종료(archived).
- 판정: `__NEXT_DATA__`/JSON-LD 파싱. **파서 실패 시 상태 동결 + 알림만**(의심 시 유지 — 오탐으로 정상 링크를
  죽이지 않는다). 쿠폰 만료는 `coupon_expires_at` 시간 기반. 플래핑은 3회 연속 soldout 시 확정.
- 상태 전이: partial_oos → 허브 뱃지·노션 갱신(발행물 무수정) / oos·coupon_expired → 숏링크 dead 전환(§10.1 불변식),
  허브 숨김, 노션 취소선, 텔레그램 알림 + 채널별 정정문 원탭 / 재입고 → "재발행할까요?" 카드 자동 생성.
- 유튜브 설명란 헬스 갱신도 PublishGateway 페이싱 적용, 조회수 상위 N개 영상만 우선(일괄 갱신 패턴 회피).

### 10.4 링크허브 (링크트리 대체)

- Next.js 1페이지 + ISR 60s. 프로필 + 고정 링크 + "오늘의 꿀매"(활성 딜 자동, oos 자동 제외) +
  착장정보(노션 동기화) + 하단 상시 고지. 링크트리 대비: 수동 편집 0, 품절 자동 숨김, 클릭 데이터 소유.
- DB 장애 시 마지막 ISR 캐시로 서빙 지속.

## 14. 남은 오픈 퀘스천 (구현 전 실측 체크리스트)

로드맵의 [실측 트랙](04-roadmap.md#2-코드-밖-리드타임-트랙)으로 관리한다. 핵심만:

1. 무신사 robots.txt·봇 차단 스택 실측 (Phase 3 첫날) — 막히면 크롤리스 모드 확정
2. 무신사 숏링크(앞단 리다이렉트) 허용 여부 — 큐레이터센터 담당자 서면 확인 (1~2주차 액션)
3. 큐레이터 링크 URL 실구조 (ULID 형식) — 현표 실링크 샘플 5~10개로 파서 검증
4. 큐레이터센터 정산 CSV 다운로드 버튼 유무 — 현표 화면 확인
5. 카카오 memo API 검수 요건·정확한 쿼터 — 도입/제외 결정
6. Meta 권한 매트릭스 (dev 모드에서 웹훅+Private Reply 실동작) — IG 자동화 선행 조건
7. 상품 상세 JSON에 사이즈별 재고 노출 여부 — 'S부터 품절' 훅 자동화 범위 결정
8. 카톡 대화 내보내기 포맷·보존 범위 — 스타일 코퍼스 규모 확정
9. jenflox.com 도메인 소유권 구조 확인 + 전용 도메인 구매
