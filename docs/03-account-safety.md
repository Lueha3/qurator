# 03. 계정 보호 설계 — 최우선 정본

> **이 문서가 프로젝트의 제1 문서다.** 다른 모든 서브시스템은 이 문서의 가드레일을
> 통과해야만 외부 플랫폼에 닿을 수 있다. 기능과 보호가 충돌하면 보호가 이긴다.
>
> 원칙 한 줄: **"현표의 계정은 코드가 직접 만지지 않는다 — 공식 API 또는 현표의 손가락만 만진다."**
>
> 본 문서는 설계 초안에 대해 **계정정지 레드팀 검증**(각 플랫폼의 어뷰징 탐지 담당자 관점 공격)을
> 수행하고 발견된 치명 1건·높음 5건·중간 5건을 전부 반영한 수정본이다. §8에 반영 내역을 기록한다.

## 1. 5대 불변식 (Invariants)

코드 리뷰·CI에서 기계적으로 검사한다. 위반 코드는 머지 불가.

1. **자격증명 연결은 4개 채널뿐** — 카카오(talk_message)·Meta·유튜브·노션. 무신사·카톡 오픈채팅은
   자격증명 제로 채널이며, 무신사 요청 경로에 인증 헤더를 넣을 수 있는 코드 경로 자체를 만들지 않는다
   (CI: 요청 스냅샷에 Cookie/Authorization 존재 시 실패).
2. **approval-first** — 승인 없이는 1바이트도 외부로 나가지 않는다. "자동 발행 모드" 토글은 존재하지 않는다.
   (예외는 §3.6의 IG 링크 카드 1종뿐이며, 그것도 사실만·총량 캡·킬스위치 하에서.)
3. **고지 불변식** — 공정위 고지문이 없는 ContentCard는 발행·복사 API가 422로 거부한다. off 옵션 없음.
4. **수집-발행 격벽** — 수집기는 현표의 계정·기기·IP와 물리적으로 분리되고, 데이터는 DB 단방향으로만 흐른다.
5. **숏링크 착지 불변식** — 자동 리다이렉트의 최종 목적지는 절대 '다른 상품의 큐레이터 링크'가 될 수 없다.
   죽은 링크는 비커미션 안내 페이지로만 간다.

## 3. PublishGateway 가드레일

모든 외부 발행은 단일 게이트웨이를 통과한다. 어댑터가 SDK를 직접 호출하는 것은 린트 규칙으로 금지.

### 3.1 행동 예산
플랫폼 공식 한도의 **10~20%를 자체 상한**으로 — 한도 근처에도 가지 않는다.
수치는 [02 §13 정책 시트](02-architecture.md#13-정책-시트--모든-수치의-단일-정본)가 정본.
예산 초과 요청은 `QUEUED_BUDGET`로 대기 + "내일 발행 예약됨" 알림. IG는 발행 전 `content_publishing_limit`
실측 교차 확인(자체 카운터와 5 이상 차이 → 카나리아 경보: 다른 도구/수동 사용 감지).

### 3.2 인간 페이스 강제
- 채널당 최소 90초 + 지터 U(0,180s), 10분 창 최대 2건, 발행 시간대 08:00~23:00 KST.
- 일괄 승인도 직렬 발행 — "승인은 배치, 발행은 사람 속도".
- **승인·발행 시간 분리 (레드팀 반영)**: 승인 건은 다음 1~3시간 창의 랜덤 슬롯으로 분산.
  다이제스트 시각도 일별 ±30분 지터. "매일 같은 시각 발행 버스트"라는 일 단위 스케줄러 지문을 없앤다.

### 3.3 approval-first 파이프라인
- 승인 카드의 가변부(훅·가격·쿠폰·링크)는 전문 표시 — 본 것과 나가는 것의 불일치 금지
  (템플릿 고정부는 버전 검증으로 보증, 템플릿 변경 첫 발행만 전 채널 전문 확인).
- 발행 직전 헬스 재확인: 재고·쿠폰 상태가 승인 시점과 달라졌을 때만 재확인 카드(시간 타이머 아님).

### 3.4 카카오 오픈채팅 콘텐츠 가드 (레드팀 반영)
'전송 주체가 사람이면 안전'만으로는 부족하다 — 콘텐츠 패턴·참여자 신고 기반 제재 경로가 별도로 존재한다.
- 게시 빈도 권고 상한 일 3~5회를 대시보드 카운터로 상시 표시.
- 숏링크/허브 도메인의 카톡 인앱 클릭 가능 여부 주기 점검 카나리아(도메인 스팸 등재 조기 감지).
- 방 공지에 영리 목적(광고성) 고지 명시 — 신고 동기 자체를 낮춘다.

### 3.5 Meta 앱 생애주기 (레드팀 반영)
- dev mode(내부 테스터)는 개발·테스트 용도다. **App Review 통과를 출시 4주 내 마일스톤**으로 잡고,
  dev mode 기간에는 발행량을 일 5건 이하로 추가 제한.
- 신생 숏링크 도메인 웜업: 첫 2주 일 2~3건 램프업 + 링크 없는 오가닉 포스트 30% 이상 혼합.
- Threads의 색상별 링크 나열 대신 링크허브 1개 링크 접기를 기본값으로.

### 3.6 IG Private Reply (유일한 자동 발송 예외)
- 허용 범위: 키워드('링크','크링') 댓글 → **사실만 담긴 링크 카드**(상품명·색상·링크·고지) 1회.
  문장 생성 없음. 댓글당 1회·7일 내(공식 메커니즘). 상품 데이터로 가변 렌더링(동일 문자열 반복 회피).
- 첫 2주 일 30건 램프업 → 이후 일 200건 캡. 부정 신호(차단·신고) 웹훅을 SignalCollector에 등록.
  킬스위치 편입. 문장형 CS는 항상 초안+수동.
- 선행 조건: Meta 권한 매트릭스 실측 통과. 실측 전에는 반자동(텔레그램 알림→사람 답글).

### 3.7 승인 채널(텔레그램) 자체 보호
- chat_id 화이트리스트. `/killall` `/resume` 등 파괴적 명령은 인라인 재확인 + 4자리 코드.
- 대시보드 웹에 킬스위치·재개 동일 토글(텔레그램 탈취·장애 시 대체 경로).
- 봇 토큰도 Vault 저장 + 회전 정책 대상.

## 4. 수집-발행 격리 (딜 레이더 격벽)

### 4.1 물리 격리
- 수집기는 발행 서버·현표의 자택/사무실 IP·현표 기기와 분리된 인프라에서 실행.
  MVP에는 크롤러가 아예 없고(수동 입력만), Phase 3 도입 시 1일차 실측으로 IP 접근성 확인 —
  막히면 **뚫지 않고 크롤리스 모드 확정**.
- 자격증명 제로: 수집기 코드베이스에 어떤 플랫폼 토큰도 주입되지 않음(환경변수 스코프 분리).
- **식별자 위생 (레드팀 반영)**: 크롤러의 UA·헤더·어떤 문자열에도 계정 연관 식별자
  (jenflox, 현표, 큐레이터 ULID, **개인/운영 이메일**)가 들어가지 않는다 — CI 검사 항목.
  UA는 봇임을 정직하게 표기하되 연락처는 계정과 무관한 서비스 전용 주소만.
  브라우저 위장·UA 로테이션·프록시 풀·captcha 해제는 금지(§9) — 차단당하면 뚫지 않고 멈춘다.

### 4.2 요청 규율
수치 정본은 [02 §13]. 핵심: 비로그인 공개 페이지만, 전역 일 600 요청 하드캡, 1req/5s+지터,
robots.txt Disallow 무조건 제외, Retry-After 준수, BLOCKED 시 자동 재개 없음(사람 해제).
가격/재고/쿠폰/랭킹 필드만 저장 — 설명문·이미지 대량 복제 금지(잡코리아 판례 안전선).

### 4.3 조회 집합 지문 완화 (레드팀 반영)
헬스체크 대상이 '현표가 링크를 발행한 상품 집합'과 1:1로 일치하면 UA를 익명화해도 계정 특정이 가능하다.
- 헬스체크 대상을 '최근 24h 클릭이 실제 발생한 링크의 상품' 중심으로 축소(집합 일치도 희석 + 요청량 감소).
- 발행 시각과 첫 체크 사이 랜덤 오프셋 1~6h(동기화 신호 제거).
- 구조적 완전 제거는 불가능하므로 **무신사 공식 제휴 트랙의 우선순위를 높이고**,
  무신사 측 항의·요청 수신 시 즉시 전면 중단이 기본 대응.

### 4.4 데이터 격벽
수집기 → 발행계는 `raw_deals` 테이블 단방향. 발행계 → 수집기 호출 없음.
수집기가 차단돼도 계정에는 흔적이 없고, 발행계 장애가 수집 패턴에 영향을 주지 않는다.

### 4.5 법적 안전선 (판례 기반)
- 여기어때/야놀자 대법원(2022, 무죄): 보호조치 없는 공개 정보의 크롤링은 정보통신망 침입 아님
  → **보호조치를 우회하지 않는 상태를 유지하는 것**이 안전선. 차단 감지 시 중단이 그 실천이다.
- 잡코리아/사람인: DB의 상당 부분을 반복·체계적으로 복제해 경쟁 서비스를 만들면 위법
  → 소량(추적 200개 상품의 4개 필드), 비경쟁(무신사로 트래픽·매출을 보내는 상생 구조 — 문서화해 소명 자료로).
- 약관 위반 → 계정 제재 경로가 실질 리스크의 본체 → "계정 비연동"이 그 답이다.

## 5. 무신사 링크 취급 불변식

1. 큐레이터 링크는 **사람이 큐레이터센터에서 생성**한다. 자동 생성 시도 없음(API 부재 + 약관).
2. 숏링크 리다이렉트는 큐레이터 링크를 **원형 무변조**로 최종 목적지에 둔다(파라미터 보존).
3. **죽은 링크의 자동 착지는 비커미션 안내 페이지만.** 대안 딜로의 이동은 사용자의 명시적 클릭을 거친다
   (레드팀 치명 이슈: 자동 302로 다른 상품 커미션 링크에 착지시키면 링크 스왑/트래픽 전용 패턴으로 판정 —
   자격 상실 직행 경로).
4. 크롤러·헬스체커는 ULID/utm 파라미터가 포함된 URL을 절대 방문하지 않는다(Fetch Gateway 하드 abort) —
   자기 클릭이 어뷰징 실적으로 잡히는 사고 원천 차단.
5. `shortlink_mode` 기본값 safe: 무신사 서면 확인 전에는 카톡·스레드·IG·유튜브에 raw 링크 직노출,
   숏링크는 자기 소유 지면(노션·허브)만. full 전환은 사람이 하고 audit_log에 기록.

## 6. 킬 스위치 · 카나리아 · 복구

### 6.1 신호 감지 (SignalCollector — 전 외부 응답 공통 미들웨어)

| 신호 | 심각도 | 조치 |
|---|---|---|
| 429 | WARN | 채널 지수 백오프 5분→15→60→240분 (Retry-After 우선) |
| 401/403 반복(토큰 유효한데) | CRIT | 채널 즉시 정지 + 긴급 알림 |
| captcha/challenge (수집기) | CRIT | 해당 도메인 24h 정지 |
| Meta 오류 368·계정 제한 subcode | CRIT | Meta 전 채널 정지 |
| IG Private Reply 차단·신고 신호 | WARN | 링크 카드 자동 발송 일시 오프 |
| 플랫폼 웹훅/이메일 경고(사람 수신) | CRIT | `/pause <채널>` 수동 트리거 |
| 숏링크 도메인 카톡 클릭 불가 감지 | CRIT | 카톡 렌더를 raw 링크로 자동 전환 + 알림 |

슬라이딩 윈도우: **채널당 1시간 내 CRIT 1건 또는 WARN 3건 → 자동 서킷 오픈.**

### 6.2 킬 스위치 계층
1. 채널 서킷브레이커 (`paused_until` + 사유. 정지 중 요청은 전부 큐잉 — 유실 없음)
2. 글로벌 킬 스위치 (DB 플래그 + `/killall`. 크론 워커도 시작 시 최우선 확인)
3. 수집기 독립 킬 스위치 (수집만 죽여도 발행·수동 입력 경로는 살아있음)

### 6.3 복구 런북 — 자동 재개 금지
자동 정지된 채널은 자동으로 재개되지 않는다. 절차:
① 알림의 원인 코드 확인 → ② 현표가 해당 플랫폼 앱/콘솔에서 계정 상태 육안 확인 →
③ `/resume <채널>` (재확인+코드) → ④ 첫 1건 재승인 발행, 24h 동안 예산 50% 모드.
CRIT 2회/7일 반복 채널은 `/resume` 잠금 — 설정 화면에서 사유 기록 후에만 해제.
**오탐의 비용(발행 지연)은 미탐의 비용(계정 정지)보다 압도적으로 싸다.**

## 9. Never List — 코드리뷰 체크리스트

1. 메신저봇R 등 비공식 카톡 봇, 알림 후킹, 카톡 UI 매크로 — 영구정지 사례 다수. 2,754명 방은 재구축 불가 자산.
2. 카카오/무신사/IG 세션쿠키 추출·재사용, 비밀번호·2FA 보관.
3. IG/Threads 비공식 라이브러리·headless 로그인 — 공식 API로 전부 대체 가능하므로 얻는 것이 없다.
4. 콜드 DM, 24h 윈도우 밖 프로모션 발송.
5. 무신사 로그인 상태의 자동화 (큐레이터센터 폴링, 링크 자동 생성 매크로).
6. 큐레이터 링크 변조, 파라미터 조작, 죽은 링크의 커미션 링크 자동 착지.
7. 크롤링 위장술 (UA 로테이션, 프록시 풀, captcha 해제) — 차단당하면 뚫지 않고 멈춘다.
8. 고지문 없는 발행 경로, 고지문 off 옵션.
9. 자동 발행 모드 (무승인 발행). §3.6의 링크 카드가 유일한 예외.
10. 플랫폼 한도 소진까지 사용, 쿼터 우회용 멀티 앱/프로젝트.
11. 크롤러 문자열(UA·헤더)에 계정 연관 식별자 포함.
12. 수집기·확장·프론트엔드에서 플랫폼 토큰 접근.

## 10. 공정위 고지 표준 (2024.12.1 개정 반영)

법적 요건: **첫 부분 배치**(끝부분·더보기·고정댓글 단독 불인정) + **확정형 문구**("받을 수 있습니다" 금지) +
한국어 + 인식 가능한 형태. 커미션 링크는 명시적 고지 의무 대상.

| 채널 | 문구 (렌더러 하드코딩 상수) | 위치 |
|---|---|---|
| 카톡 오픈채팅 | `(광고) 아래 링크로 구매 시 수수료를 받습니다` | 메시지마다 첫 줄 (분할 시 각 파트) |
| 스레드 | `[광고] 큐레이터 링크 — 구매 시 수수료를 받습니다` | 본문 첫 줄 |
| IG 캡션 | `[광고] 이 게시물의 링크로 구매 시 수수료를 받습니다` | 본문 첫 줄 (+릴스 영상 내 자막 권장) |
| IG 고정댓글 | `[광고] 아래 링크로 구매 시 수수료를 받습니다` | 첫 줄 |
| 유튜브 설명란 | `(광고) 아래 큐레이터 링크로 구매 시 무신사로부터 수수료를 받습니다` | **설명란 전체의 첫 줄 (접힘 전 노출 영역)** |
| 노션/링크허브 | 동일 문구 콜아웃/배너 | 페이지 최상단 / 링크 목록 상단 상시 |

- 3중 방어: ① 렌더러 하드코딩 삽입(템플릿 DSL에는 위치 슬롯만, 내용·삭제 불가) →
  ② 발행·복사 API의 disclosure_ok 검증(422 거부) → ③ ContentCard 불변 이력으로 전수 감사(3년 보존).
- **협찬 영상은 텍스트 삽입만으로 '고지 완료' 표시 금지** — 제목 초반 [광고], 영상 내 고지,
  유튜브 '유료 광고 포함' 체크를 사람 체크리스트로 승인 카드에 포함하고, 미체크 시 sponsor_deals 상태 전이 차단.
- 지침 개정 시 문구 상수만 버전업 (2026 행정예고: AI 가상인물 고지 등 후속 개정 모니터링).

## 11. 감사 로그 (이의제기 증적)

목적: 제재 시 "전부 사람이 승인한 공식 API 사용"임을 입증, 공정위 이슈 시 고지 이력 입증.

- append-only `audit_log` (RLS로 INSERT만): 승인 카드 스냅샷 → 현표 승인 이벤트(텔레그램 user_id·ts) →
  발행 페이로드 해시 → 플랫폼 응답 ID가 하나의 `approval_ref` 체인. 5초 안에 조회 가능한 뷰.
- 기록: 승인/수정/스킵, 발행 시도·응답, 고지 검증 결과, 카나리아·킬스위치 작동, shortlink_mode 전환,
  수집기 요청 로그(URL·ts·응답코드 — 본문 미저장).
- 보존 3년 (표시광고법 제재 시효 고려), 월 1회 아카이브. 토큰·PII 기록 금지(마스킹 미들웨어 공용).
- 백업: Supabase Pro PITR 또는 pg_dump 일일 크론. 수동 입력 데이터(코퍼스·착용감·정산 원본) 주간 export.
