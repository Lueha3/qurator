# 04. 개발 로드맵 — 단계별 계획·KPI·비용

> 실현성 검증에서 "초안의 1주차 범위는 실제 4~6주 분량이며 크롬 웹스토어 심사·Meta 앱 설정 같은
> 코드 밖 리드타임이 일정에 없다"는 지적을 받았다. 본 로드맵은 그것을 반영한 **현실 일정**이다.
>
> 순서의 원칙 (실사용성 검증 결론):
> **"입력→배포 루프의 습관화(1~2주) → 헬스체크로 신뢰 획득 → 그 다음에 레이더로 발굴 자동화."**
> 딜 레이더·스코어러·CS 초안·대시보드를 첫 2주에 넣지 않는다 — 콜드스타트기의 낮은 추천 정확도와
> 높은 카피 수정률은 도구 신뢰를 깎아 코어 습관화를 방해한다.

---

## 0. 시간 목표에 대한 정직한 계산

실사용성 검증이 하루 시뮬레이션(아침 다이제스트 → 낮 촬영 → 저녁 실시간 딜 → 밤 CS)으로 계산한 결과:

| 단계 | 일일 반복 작업 시간 | 근거 |
|---|---|---|
| 현재 (수동) | **~3시간** | 딜당 30~60분 × N + CS 30분+ |
| Phase 1~2 (입력→배포 루프) | **60~75분** | 재입력 0회·고지 자동·카톡 원탭. 남는 시간의 60%가 큐레이터센터 링크 수동 생성 |
| Phase 3~4 (레이더 + 병목 해소 3종 적용 후) | **25~35분** | 대표 링크 기본값 + 배치 링크 세션 + 텔레그램 콕핏 + IG 링크 카드 자동 |

- "3시간 → 10분"은 무신사가 링크 생성 API를 제공하지 않는 한 정직한 숫자가 아니다.
  **60~75% 절감(Phase 2) → 80~85% 절감(Phase 4)** 이 이 설계가 약속할 수 있는 수치이며,
  '링크 생성 분/딜'을 주간 지표로 추적해 이 계산을 계속 검증한다.
- 무신사 공식 제휴(링크 API)가 성사되면 그때 10분대가 열린다 — 그래서 제휴 트랙이 로드맵에 있다.

## 1. 단계별 계획

### Phase 0 — "재입력 제로" (1주차) : 외부 API 0개, 심사 0개

> 실현성 검증의 축소 권고 그대로: **웹 폼 하나로 시작한다.** 그래도 핵심 가치가 성립한다.

| 구현 | 내용 |
|---|---|
| 코어 DB | creators/products/variants/deals/curator_links/content_cards/posts (스키마 정본 [02 §3]) |
| 결정론적 렌더러 | 채널 4종(카톡 풀버전·스레드·IG 고정댓글·노션 텍스트) + 고지 하드 삽입 + 글자수 검증 |
| 웹 폼 | URL+가격+쿠폰 수동 입력 → 큐레이터 링크 붙여넣기 → 채널별 [복사] 버튼 |
| AI 훅 초안 | Claude API 1종 (실패해도 빈 훅으로 진행) |

**Day 1 사용 시나리오**: 상품 URL과 센터에서 만든 링크를 폼에 붙여넣으면 → 고지 포함 4채널 완성 텍스트가
클립보드로. **같은 정보 재입력 4~5회 → 0회가 첫날부터 체감된다.** 온보딩 0분(취향 입력·코퍼스는 나중).

### Phase 1 — 텔레그램 콕핏 + 카톡 루프 (2~3주차)

| 구현 | 내용 |
|---|---|
| 텔레그램 봇 | URL 던지기 캡처, **모바일 공유시트 진입**, 카드 상태 전이(후보→링크 대기→발행 승인), [훅만 교체] 수정, 카톡 코드블록 전달 |
| 링크 입력 완결 | 봇 대화에 큐레이터 링크 붙여넣기 → ULID 파싱·variant 매칭·재렌더 (**일상 루프를 텔레그램+카톡 2앱으로 압축**) |
| 대표 링크 기본값 | 색상별 링크는 옵트인으로 강등 |
| 전용 도메인 | 구매 + 복사 웹뷰(`/copy/{post_id}`) 배포 |
| 카카오 memo | 실측 결과에 따라 도입 or 제외 확정 |

### Phase 2 — 자동 발행 + 죽은 링크 방어 (4~6주차)

| 구현 | 내용 |
|---|---|
| Threads 어댑터 | 자동 발행 (dev mode, 일 5건 제한 + 도메인 웜업 규칙) |
| Notion 어댑터 | 착장 페이지 자동 생성 |
| 링크허브 v1 | 링크트리 대체 (활성 딜 자동, oos 제외, 상시 고지) — 프로필 링크 1회 교체 |
| 링크 헬스체커 | **정규 상품 URL만**, 티어 주기, 오탐 시 동결. 허브·노션 자동 갱신 + 카톡 정정문 원탭 |
| 크롬 확장 | 1주차 제출한 스켈레톤 위에 캡처 기능 배포 (PC 보조 경로) |
| 숏링크 (safe 모드) | 자기 소유 지면만 적용해 계측 표본 확보. 무신사 확인 시 full 전환 |

**Phase 2 종료 = "이거 없으면 못 살아" 코어 완성** (실사용성 검증이 정의한 4종:
① URL→4채널 카드+원탭 복사 ② 봇 안 링크 완결 ③ 헬스체크+자동 숨김+정정 알림 ④ 링크허브).

### Phase 3 — 발굴 자동화 (7~10주차)

| 구현 | 내용 |
|---|---|
| 딜 레이더 | **1일차 robots.txt·차단 스택 실측** → 통과 시 정책 시트 수치로 가동, 막히면 크롤리스 모드 확정 |
| 이벤트 감지 | PRICE_DROP/COUPON/SIZE_SELLOUT/RANK_SURGE/RESTOCK |
| 스코어러 P1+P2 | 룰 + 경계딜 LLM 판정. 다이제스트 3회/일 + 방해금지 모드 |
| IG 발행 어댑터 | App Review 통과 후 (릴스는 반자동 유지) |
| IG 링크 카드 | 권한 매트릭스 실측 통과 시 자동, 아니면 반자동 |
| 배치 링크 세션 | 아침 다이제스트 승인분 일괄 처리 UX |

### Phase 4 — 피드백 루프·운영 완성 (11~14주차)

| 구현 | 내용 |
|---|---|
| 통합 대시보드 | 오늘/딜 성과/채널 인사이트 3화면. 정산 CSV(또는 스크린샷 Vision) 업로드 |
| 성과→스코어 피드백 | 주 1회 EMA 배치 (초기 4주 수집만) |
| CS 초안 | 착용감 DB + 사이즈 FAQ 초안 (자동 발송 없음) |
| 유튜브 어댑터 | 설명란 자동(고지 최상단)·고정댓글 반자동 |
| 스타일 코퍼스 고도화 | 카톡 export 임포트, 수정 전후 쌍 자동 축적 |

### Phase 5 — 확장 트랙 (3~6개월, 병행)

- **무신사 공식 제휴 제안**: 상품 피드/딜 API, 링크 생성 API, 정산 export.
  활성 큐레이터 4,400명·거래액 1,200억은 무신사에게도 큐레이터 생산성 도구의 가치가 있다.
  **제휴 성사 시 크롤러 전면 폐기가 이 시스템의 성공 시나리오다.**
- 협찬 브리프(Gmail 읽기 전용), 주간 요약 뉴스레터 초안.
- 카카오톡 채널(친구톡 브로드캐스트, 건당 15~30원) 이전 실험 — 커미션 수익 > 발송비 검증 후.
- SaaS 결정 게이트: §5 참조.

## 2. 코드 밖 리드타임 트랙 (1주차에 전부 착수)

코드와 무관하게 시간이 걸리는 것들 — 늦게 시작하면 전체 일정을 막는다.

| # | 항목 | 기한 | 블로킹 대상 |
|---|---|---|---|
| 1 | 크롬 웹스토어 개발자 등록($5) + 확장 스켈레톤 선제출 | 1주차 | Phase 2 확장 배포 |
| 2 | Meta 앱 생성 + 테스터 설정 + **App Review 제출 준비** | 1주차 시작, 4주 내 통과 목표 | Phase 2 Threads / Phase 3 IG |
| 3 | 무신사 큐레이터센터 담당자에게 숏링크(앞단 리다이렉트) 허용 여부 서면 확인 요청 | 1~2주차 | shortlink full 모드 |
| 4 | 전용 도메인 구매 (현표 DNS 완전 소유) | 1주차 | 링크허브·복사 웹뷰·숏링크 |
| 5 | 카카오 디벨로퍼스 앱 생성 + talk_message 검수 요건·쿼터 실측 | 1주차 | memo API 도입 결정 |
| 6 | 현표 실측 협조: 큐레이터 링크 샘플 5~10개(ULID 파서 검증), 정산 화면 CSV 버튼 유무, 카톡 대화 내보내기 1회 | 1~2주차 | 파서·대시보드·코퍼스 |
| 7 | Meta 권한 매트릭스 실측 (dev 모드 웹훅+Private Reply 실동작) | Phase 3 전 | IG 링크 카드 자동화 |
| 8 | 무신사 robots.txt·봇 차단 스택 실측 | Phase 3 1일차 | 크롤러 가동/크롤리스 결정 |
| 9 | 백업 셋업 (Supabase Pro PITR 또는 pg_dump 크론) | Phase 0 | 전체 |

## 3. KPI

| 지표 | 측정 | 4주 | 8주 | 14주 |
|---|---|---|---|---|
| **계정 경고/제재 건수** | 전 플랫폼 | **0** | **0** | **0 (영구)** |
| 일일 반복 작업 시간 | 주간 자가 기록 + 도구 로그 | 75분 | 60분 | 25~35분 |
| 딜 1건 발행 소요 (발굴→4채널) | posts 타임스탬프 | 8분 | 5분 | 3~5분 |
| 링크 생성 분/딜 | 세션 로그 | 측정 시작 | 2분 | 1분 (배치) |
| 재입력 횟수/딜 | 정성 | 0회 | 0회 | 0회 |
| 죽은 링크 감지 시간 | 헬스체커 | — | ≤24h | ≤6h (활성 딜) |
| AI 훅 승인률 (무수정) | feedback | — | 50% | 60~70% |
| 스코어 승인률 (레이더) | feedback | — | — | 50→70% 궤적 |
| 주간 도구 사용일 | 세션 로그 | 5+/7 | 6+/7 | 7/7 |

- **최우선 KPI는 계정 경고 0건이다.** 다른 모든 지표가 좋아도 이것이 깨지면 실패다.
- 승인률 분모에서 expired/미열람은 제외(라벨 오염 방지 — [02 §6]).

## 5. SaaS 확장 게이트 (4,400명 큐레이터)

다음 조건이 **모두** 충족되기 전에는 멀티테넌트 기능을 만들지 않는다 (creator_id 스키마만 유지):

1. 현표의 주간 사용일 7/7이 4주 연속 (습관화 증명)
2. 일일 반복 시간 ≤40분 달성 (가치 증명)
3. 계정 경고 0건 유지 3개월 (안전 증명)
4. 무신사와의 관계 정립 (제휴 협의 개시 또는 최소한 묵인 확인) — **무신사와 적대 관계인 채로
   4,400명에게 파는 것은 전원의 계정을 위험에 빠뜨리는 일이다**
5. Meta App Review·카카오 비즈앱 등 심사류가 다인 사용자 기준으로 통과

확장 시 추가 과제: 크리에이터별 템플릿/톤 프로필(스키마 이미 지원), OAuth 온보딩 플로우,
공정위 고지 문구의 플랫폼별 검증 자동화, 과금.

## 6. 리스크 레지스터

| 리스크 | 확률 | 영향 | 대응 |
|---|---|---|---|
| 무신사가 숏링크 불허 | 중 | 중 | safe 모드가 기본값이므로 영향 없음 — 카톡·스레드 raw 링크 유지, 계측은 자기 소유 지면으로 한정 |
| 무신사 크롤링 차단 | 중~높음 | 중 | **크롤리스 모드가 기본 시나리오** — 수동 입력+확장으로 100% 동작. 제휴 트랙 가속 |
| Meta App Review 지연/거절 | 중 | 중 | dev mode 저용량 운영 지속 + 반자동 폴백. 스코프 최소화로 재신청 |
| 카카오 memo 검수 거절 | 중 | 낮음 | 텔레그램 주 경로라 서비스 영향 0. 계정에 자격증명 0개 유지 |
| 도메인 스팸 등재 (카톡/Meta) | 낮음~중 | 높음 | 웜업·빈도 가드·카나리아 조기 감지, 등재 시 raw 링크 자동 전환 |
| AI 훅 품질 미달 (콜드스타트) | 높음(초기) | 중 | 훅만 교체 UX + 2안 택1 + 팩트 템플릿 폴백. 수정쌍 자동 학습 |
| 파서 깨짐 (무신사 개편) | 중 | 낮음 | 폴백 체인(JSON-LD→NEXT_DATA→DOM→수동 폼) + 상태 동결 원칙 |
| 현표가 도구를 안 씀 | 중 | **치명** | Phase 0 첫날 가치 체감 + 온보딩 0분 + 2앱 루프 + 주간 사용일 KPI 추적. 4주차 사용일 5/7 미만이면 기능 추가 중단하고 마찰 제거에 전력 |
| 단일 개발자 버스 팩터 | — | 중 | 본 문서 체계 + 정책 시트 DB화 + 감사 로그로 운영 지식의 문서화 유지 |
