# qurator (HoneyFlow)

> **"한 번 발굴한 꿀템이 카톡·스레드·인스타·노션에 채널별 맞춤 포맷으로 자동 확산되고,
> 성과 데이터가 다시 발굴 우선순위를 결정하는 크리에이터용 멀티채널 커머스 자동화 플랫폼"**

1차 사용자: 현표(maison_jenflox) — 무신사 패션 큐레이터 겸 1인 커머스 미디어 운영자.
장기: 동일 문제를 가진 무신사 활성 큐레이터 대상 범용 SaaS.

---

## 절대 원칙 (모든 설계·코드 리뷰의 기준)

1. **계정 보호가 기능보다 우선한다.**
   현표의 카카오·무신사·Meta·유튜브 계정은 그의 밥줄이다.
   - 계정에 연결되는 것은 **공식 API + OAuth**뿐이다.
   - 공식 API가 없는 채널(카톡 오픈채팅)은 **반자동**(시스템이 완성본 생성 → 사람이 전송)이다.
   - 비공식 봇, 세션 쿠키 재사용, 비밀번호 위임, 리버스 엔지니어링된 API 호출은 **어떤 경우에도 금지**한다.
   - 수집(크롤링)은 현표의 계정·기기·IP와 **완전히 격리**하고, 로그인 없는 공개 페이지만, 저빈도로 접근한다.
   - 모든 발행은 **휴먼 승인 게이트** 뒤에 있다. 시스템은 초안을 만들고, 사람이 결정한다.
2. **실질적 시간 단축.** 매일 ~3시간의 반복 작업 → 60~75분(6주) → 25~35분(14주).
   승인 1건 30초 이내, 일상 루프는 텔레그램+카톡 2개 앱 안에서 완결.
   크롤링이 전부 막혀도 가치가 남는 구조(수동 URL 입력이 1급 시민)로 만든다.
3. **규정 준수를 시스템이 보증한다.** 공정위 경제적 이해관계 고지 문구는 템플릿 엔진이 자동 삽입한다.

## 지금 여기 있는 것: Phase 0~1

### Phase 0 — "재입력 제로" (웹 폼)

**외부 플랫폼 API 0개, 계정 자격증명 0개.** 상품 URL·가격·큐레이터 링크를 웹 폼에 한 번 입력하면
공정위 고지문이 하드 삽입된 카톡·스레드·인스타·노션용 완성 카드 4종이 생성되고, 원탭 복사로 재입력이 사라진다.

- **렌더러**(`src/lib/renderer.ts`)가 안전의 핵심이다: 가격·재고·링크는 이 파일이 조립하고, AI는
  훅 문장만 생성한다(`src/lib/ai-hook.ts`, 실패해도 빈 훅으로 정상 렌더). 고지문은 채널별 상수로
  하드코딩 삽입되며(`src/lib/disclosure.ts`), 발행 전 별도 검증 게이트가 한 번 더 확인한다.
- 채널 글자수 제약(스레드 480자 등)을 넘으면 자동 축약 사다리가 적용되고, 고지문과 최소 1개 링크는
  어떤 단계에서도 제거되지 않는다.

### Phase 1 — "텔레그램 콕핏" (모바일에서 완결)

일상 루프가 **텔레그램 + 카톡 2개 앱** 안에서 끝난다.

```
무신사 앱에서 상품 공유 → 텔레그램 봇
  → [후보 카드]      봇이 URL을 단발 fetch·파싱해서 상품 정보를 채워 보여준다
  → [링크 대기]      [이거 올릴래] 탭 → 큐레이터센터 링크를 대화에 붙여넣기
  → [발행 승인]      카톡 문구 미리보기 (본 것 = 나가는 것)
  → [승인 완료]      카톡용 완성 텍스트를 코드블록으로 전달 → 카톡에 붙여넣기
```

카드는 **1장이 상태 전이한다** — 딜마다 메시지가 쌓이지 않는다.

계정 안전의 중심은 **Fetch Gateway**(`src/lib/fetch-gateway.ts`)다. 무신사로 나가는 모든 HTTP가
이 관문 하나만 통과한다(ESLint가 직접 `fetch` 호출을 차단한다):

| 가드 | 내용 |
|---|---|
| 커미션 URL 하드 abort | `utm_term` ULID 등이 붙은 URL은 절대 방문하지 않는다 — 자기 클릭이 어뷰징 실적으로 잡히는 사고 차단. 리다이렉트 **홉마다** 재검증 |
| 자격증명 제로 | 헤더를 호출부가 넘길 수 없는 구조 → Cookie/Authorization이 실릴 경로 자체가 없다. 쿠키 저장소 없음 |
| robots.txt | RFC 9309 준수. **5xx·조회 실패는 전면 금지**(4xx만 허용), 24h 캐시 상한, 쿼리스트링 포함 매칭 |
| SSRF | 호스트 화이트리스트 + `ipaddr.js` 화이트리스트 방식(unicast만 통과) + 리다이렉트 홉마다 DNS 재검증 |
| 예산·페이싱 | 일 600건·시간당 60건·요청 간 5초+지터. DB 설정과 코드 하드캡 중 **더 보수적인 값**이 이긴다 |
| 차단 시 정지 | 캡차·차단 페이지 감지 시 서킷을 열고 **자동 재개하지 않는다**. 뚫으려는 재시도 코드는 존재하지 않는다 |

텔레그램은 현표의 밥줄 계정과 무관한 별도 채널이라 리스크가 0이며, 봇 메시지는 **항상 링크 프리뷰를 끈다**
(켜두면 텔레그램 서버가 큐레이터 링크를 프리뷰용으로 방문해 게이트웨이를 우회한다).

### 시작하기

```bash
npm install
cp .env.example .env
npx prisma migrate deploy    # DB 스키마 적용
npm run db:seed              # 현표(creator) 레코드 생성

# 웹 접근 암호와 링크 서명 키 생성 (둘 다 필수 — 비어 있으면 웹 전체가 차단된다)
echo "APP_ACCESS_TOKEN=$(openssl rand -base64 32)" >> .env
echo "APP_SECRET=$(openssl rand -base64 32)" >> .env

npm run dev                  # http://localhost:3000/?k=<APP_ACCESS_TOKEN 값>
```

> 대시보드와 API는 카드 본문을 서빙하고, 그 안에는 큐레이터 링크가 원본 그대로 들어 있다
> (`utm_term` ULID 포함). 인증 없이 열어두면 검색봇·스크래퍼가 현표 실적으로 클릭을 쌓아
> 어뷰징으로 판정될 수 있어, 미들웨어가 **토큰 미설정 시 전면 차단**한다(fail closed).
> 복사 웹뷰만 예외이며, 그 경로는 HMAC 서명 + 24시간 만료 토큰으로 스스로를 방어한다.

텔레그램 봇까지 쓰려면 `.env`에 두 값을 채운다:

1. `TELEGRAM_BOT_TOKEN` — [@BotFather](https://t.me/BotFather)에서 `/newbot`으로 발급
2. `TELEGRAM_ALLOWED_CHAT_IDS` — 봇에게 아무 메시지나 보낸 뒤
   `https://api.telegram.org/bot<TOKEN>/getUpdates`에서 `message.from.id` 확인
   (**비워두면 봇이 모든 메시지를 거부한다** — 봇 사용자명은 공개라 아무나 말을 걸 수 있기 때문)

```bash
npm run bot     # 폴링 모드로 봇 실행 (로컬 개발)
```

프로덕션은 `/api/telegram/webhook` 라우트를 쓴다(`setWebhook`의 `secret_token`을
`TELEGRAM_WEBHOOK_SECRET`과 맞춰야 한다). 텔레그램은 같은 토큰에서 webhook과 폴링을
동시에 허용하지 않으므로 둘 중 하나만 쓴다.

`ANTHROPIC_API_KEY`는 선택 사항이다 — 없으면 훅 문구만 비고 나머지는 전부 동작한다.

```bash
npm test              # 불변식 테스트 (고지·커미션URL·SSRF·robots·서명·상태머신 E2E)
npm run build         # 프로덕션 빌드
npm run gateway status  # 서킷·킬스위치·사용량 확인
```

### 게이트웨이 운영

무신사가 자동 요청을 차단하면 서킷이 열리고 **자동으로 재개되지 않는다** — 자동 재시도는
"차단을 뚫으려는 시도"가 되어 법적 안전선(보호조치 우회 없음)에서 벗어나기 때문이다.
해제는 사람이 계정 상태를 눈으로 확인한 뒤에만 한다:

```bash
npm run gateway status              # 무엇이 왜 막혔는지
npm run gateway resume www.musinsa.com
npm run gateway kill / unkill       # 글로벌 킬 스위치
```

### 아직 없는 것 (Phase 2+)

스레드/노션/IG 실제 발행 어댑터, 링크 헬스체커, 링크허브(링크트리 대체), 딜 레이더 자동 발굴,
통합 대시보드 — 전부 [로드맵](docs/04-roadmap.md)에 있고 현재 스키마 위에 그대로 쌓는다.

> **배포 주의**: 게이트웨이의 레이트리밋·서킷 상태는 DB에 있다. SQLite는 파일시스템을 공유하는
> 단일 프로세스에서만 이 한도를 강제할 수 있으므로, 서버리스에 여러 인스턴스로 올리면 한도가 무의미해진다.
> Phase 1의 봇은 롱리빙 프로세스(`npm run bot`)로 돌리는 것을 전제로 한다. 서버리스로 갈 때는
> Postgres로 이전하고 원자적 카운터로 바꿔야 한다.
